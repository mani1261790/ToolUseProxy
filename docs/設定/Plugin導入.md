# プラグインの導入・更新・解除

[導入と初期設定](../../QUICKSTART.md) · [対応範囲](../../SUPPORT.md) · [文書一覧](../索引.md)

通常の導入はクイックスタートにまとめています。この文書では配布物と設定の境界を説明します。

## 配布物と保存先

プラグインの定義、5種類のHook、セットアップSkill、Python実行コードを同じ版として配布します。実行コードはCodexが渡す `PLUGIN_ROOT` から起動し、変更される設定や `events.db` は専用の `PLUGIN_DATA` に保存します。プロジェクト内の任意のスクリプトをプラグインの代わりに実行しません。

`public-alpha` は公開版の更新チャンネルです。固定版を使う場合は `v0.2.0-alpha.16` のような公開タグを指定します。`main` の更新と、公開版・インストール済みプラグインの更新は別です。

## インストールと更新

```sh
codex plugin marketplace add mani1261790/ToolUseProxy --ref public-alpha
codex plugin add tooluseproxy@tooluseproxy
codex plugin list --json
```

更新時は次を実行します。

```sh
codex plugin marketplace upgrade tooluseproxy
```

実際のインストール先にある `hooks/run_cli.sh --version` で実行する版を確認してください。古いキャッシュのSkillや別のチェックアウトを、現在の実行コードと混同しないでください。Hook定義が変わった場合は再確認し、Codexを再起動して新しいタスクで確認します。

## 初期設定と登録

[クイックスタート](../../QUICKSTART.md)の順に、対象プロジェクトで初期設定し、指定したファイルを登録します。初期設定はログ画面も起動します。設定・保護登録・ログ画面の起動結果は別々に報告します。

v0.1の「ローカル処理のみ」という同意は、新しいモデルへのデータ送信に流用しません。旧登録ファイルだけがある環境を、保護登録済みのv0.2環境と扱うこともありません。既存データを削除して移行する手順にはしないでください。

## 解除とデータの保持

プロジェクトからの解除は[Setup／Unsetup](../運用/Setup-Unsetup.md)を参照してください。管理者用部品の導入と対象登録、OS認証が必要です。認証や確認ダイアログをエージェントに代行させません。

プラグインの削除と保存データの削除は別です。保存・保持の方針は[プライバシー](../../PRIVACY.md)にまとめています。問題発生時も、根拠となるログや登録を無断で消して復旧扱いにしません。

## 過去の検証

v0.1の更新・削除・復元試験は[旧導入記録](../history/v0.1/Plugin導入.md)に保存しています。その手順や実績を、v0.2の受入確認へ読み替えないでください。現在の実Hookの検証は[alpha.16検証](../運用/alpha16検証.md)を参照してください。
