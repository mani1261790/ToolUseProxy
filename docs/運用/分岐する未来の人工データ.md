# 分岐する未来の人工データ

Issue #133 / F01。人工ファイルの明示的な移動・Base64変換・道具出力による分岐を
記録し、予測時点の入力と、その後の経路正解を別々に保存する。通常Pluginからは
起動せず、実利用DB、利用者の保護リスト、実情報を入力にしない。

## 実行

Dockerが起動している環境で、保護リストを含めない専用checkoutから明示実行する。

```sh
python3 -m hook_monitor.evaluation.flow_forecast.runner \
  --repository /absolute/path/to/clean-checkout \
  --output-directory /absolute/path/to/new-forecast-run
```

既定は保護文字列のplain送信と公開文字列のBase64送信。
`--variant alternate`は保護Base64と公開plainを使う。1回の実行は2課題から
「ローカルで終了」「送信」「保存して送信」の3分岐を、防御有効・観測専用で
それぞれ実行する。合計12分岐、道具出力の前後2時点で切るため24 continuation、
8 prefixとなる。分岐前は各1/3、出力後は対応する分岐の確率1とする。
この確率は人工課題の設計値であり、自然な利用頻度ではない。

ファイル操作は一時ディレクトリー内で固定の人工bytesだけを使い、読み取り・保存後の
bytes一致、Base64の可逆性を確認する。各分岐は同じ初期ファイルから作り直す。
送信は既存#129/#130の隔離Docker基盤を使用する。検査・実行対象のPythonに埋める
bytesと、人工ファイルから得たbytesの一致を送信前に確認する。

送信の許可・拒否は独立したguardで得て、受信事実はreceiverの記録で確定する。
最初に公開受信・保護受信・保護停止の3対照を確認する。送信試行は対照込み11件、
ローカル終了も含む試行は15件で、1組20試行以内。既定600秒、最大1800秒、保存1GiB。
外部操作には既存の個別timeoutがあり、送信前にも全体時間・件数・容量を確認する。

失敗・中断時も専用保存先を残す。未確定送信はTrialStoreの予約へ残り、同じ保存先への
再実行は拒否する。自動再送・自動再開は行わない。`report.json`が完成記録であり、
`intent.json`だけの出力先を完成データとは扱わない。コンテナ・networkは既存の
所有権付きcleanupを使う。通常Pluginを有効化しない。

## 保存形式と正解

- `dataset/inputs.json`: 予測時点以前の操作、観測済み情報物、既知の保護登録、
  道具・版・観測開始前から既知のplain/Base64条件。root課題IDはモデル入力の外に置く。未来の親関係・受信結果・判定理由・
  分岐確率は入力に持たせない。道具出力が見えた後のprefixだけにその出力が入る。
- `dataset/targets.json`: 続き、独立した移動根拠、受信、途中終了、方針条件。
  防御有効と観測専用は別条件。同じprefixからの対照を持たない固定分布は拒否する。
- `dataset/splits.json`: 元課題・同一snapshot・明示した短縮版/言い換えの連結群を
  丸ごとtrain/calibration/testへ分ける。行単位に分割しない。既定比率80/10/10。
  plain/Base64の派生課題も同じ元課題へまとめる。prefix集合と関連付け、seedを凍結し、集合の変更を別版として検出する。
- `dataset/summary.json`: 条件・1/2/4/8手ごとのyes/no/unknown、途中終了、分割件数。
  意味的由来・選択・タスクをまたぐ関係は拡張対象として別欄に件数を示す。
- `dataset/manifest.json`: 最後に書く完成seal。全ファイルのdigest、dataset版、分割digest。
  読み込み時に構造・参照・時点・分布・分割・集計を再検証する。未知の入力field、
  欠落、改変、重複JSONキー、過大データ、symlinkを拒否し、既存出力を上書きしない。
- `trials/`と`receiver-evidence.jsonl`: 実送信の事前予約・Hook判断・独立受信記録。
  経路のreceipt digestは後者の記録に対応する。ファイル移動のdigestは固定bytesの
  検証結果を参照する。実利用のpayloadやDBは含めない。

既知の移動だけでsourceから確認済みsinkへつながった経路を正解にする。
不明な親関係を推測で補わない。停止・時間切れ・受信観測不足はcensored/unknownで、
「届かなかった安全例」にしない。確認できた公開送信・ローカル終了は正常作業に含める。

## 既存の自由探索記録

```sh
python3 -m hook_monitor.evaluation.flow_forecast.search_import \
  --search-directory /absolute/path/to/completed-synthetic-search \
  --output-directory /absolute/path/to/new-import
```

#130の専用search.sqlite3とtrials.sqlite3をmode=ro/query_onlyで読む。
アプリID・版・run・attempt・step・tool_use_id・保存済みplanを照合し、未完了runや
未確定送信予約を拒否する。モデル呼び出し・Docker実行・書き換えはしない。

元の探索全体を同じ学習区分へまとめ、historical_observation/adaptive_searchとして
取り込む。頻度を自然な確率に変換せず、存在しない観測専用対照を作らない。
独立した受信結果は`import-evidence.json`に残すが、旧記録には中間の移動根拠がないので
その経路はunknownとする。独立したfresh guardの操作を、状態を共有する複数手の
経路へつなぎ直さない。未観測の予定操作もunknownとして残す。

## 検証範囲

未来出力の変更によるprefix不変性、未来参照の拒否、既知/未知経路、停止のcensor、
元課題・同一snapshot・短縮版の分割漏れ、artifact再読込・改変拒否、探索記録の
読み取り専用・欠落対照・不明経路の保持を回帰試験する。

この実装は人工データ生成の基盤。初回は小さな2課題の動作確認であり、
これをそのまま最終評価には使わない。F02で独立課題数と採用条件を凍結する。
意味的由来・任意の道具・未知のタスク境界、実モデル内部の状態再開、native Hook、
stateful guardの複数手追跡、汎用的な未来予測の有効性は証明していない。

（対照込み）、24 continuation・8 prefixを保存・再読込。各組20 completed、
4 blockedとなり、blockedは全horizonでunknown。公開受信・保護受信・保護停止の
3対照は両組とも成立した。実行版digestは
`4696febf04e1fb3e5cf12eb75d5b6b7a281e29b2fe796def9e7cf7bda5ef72d7`。
ローカル証拠は`/private/tmp/tooluseproxy-133-grouped-initial`と
`/private/tmp/tooluseproxy-133-grouped-alternate`。恒久保存を保証する場所ではない。

既存の`/private/tmp/tooluseproxy-130-composed-smoke`からの取り込みは
`/private/tmp/tooluseproxy-133-grouped-import`へ保存。実Codex探索の停止3件を

plain/Base64の2組を結合した48 continuationでも、元課題群は2件のまま。
変換条件だけを理由に学習と評価へ分かれないことを保存済み実行記録でも確認した。
