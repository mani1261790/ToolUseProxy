その実確認中、3.4GBまで増えた保存DBが冷えた状態では操作前の判定に約12秒かかり、Codexの10秒制限で判定が打ち切られて操作が始まる問題を確認しました。Issue #122では次を実装しました。

- 現在の実行だけを読む索引を必ず使い、不要な全体走査を避ける
- 操作前の内部判定が7秒を超えた場合、途中結果を捨てて固定の停止結果を返す
- Codex側の操作前Hook制限を15秒にし、内部の停止結果を先に受け取れるようにする
- 必要な索引がないDBは、無理に検索せず安全側で停止する

PR #123を`main`へ取り込み、`v0.1.0-alpha.15`をGitHubの事前公開版として公開しました。PR #124で同じ内容を`public-alpha`へ反映しました。現在のCodexもalpha.15へ更新し、変更された操作前Hookを正規の確認画面から確認済みにしました。

新しいCodex実行で、設定済みのPromptPredictionでは次を確認しました。

- 番号を直接書いた`gh issue view 122 ...`は操作前判定を通過し、コマンドが開始した
- 変数を使った`n=122; gh issue view "$n" ...`は操作前に停止し、コマンドは始まらなかった
- 同じ実行番号で開始、操作前、操作後、終了の記録が保存された
