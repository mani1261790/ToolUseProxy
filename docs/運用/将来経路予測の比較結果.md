実装した比較処理は動作するが、F01の2課題群ではF02の最終試料数を満たさず、

## 再実行

```sh
python3 -m research.flow_forecast.compare prepare \
  --dataset /absolute/path/to/sealed/dataset --output /new/path/plan.json
python3 -m research.flow_forecast.compare evaluate \
  --dataset /absolute/path/to/sealed/dataset --plan /new/path/plan.json \
  --output /new/path/test-report.json
```

学習はtrainだけ、閾値と確率比較の基準方式はcalibrationだけで決める。
observe/enforce、horizon 1/2/4/8、目標偽陽性率1%/5%を別々に報告する。
モデル・データ・分割・規約・選択のdigestを計画に固定し、evaluate時に再計算して照合する。
既存成果物の上書きは拒否。testが空なら空のまま報告し、trainへの自動切替はしない。
動作確認に限り明示的な `--partition train` を使い、training_smoke_onlyと記録する。

CPUのみで全処理300秒・プロセスピークRSS 1GiB以内を協調的に検査する。
出力は64MiBまで。資源上限はOSによる強制隔離ではなく、失敗時に自動延長もしない。
通常Plugin、実利用DB、保護設定、Hook、自動停止には接続しない。

## 比較の内容と限界

4基準方式、F03の操作列モデル、3種類の推論部品除去を同じデータで比較する。
道具、課題種別、データ版別の集計も出す。道具別の層は予測後の採点側で作り、
未来の道具を予測入力へ渡さない。データ版は生成エージェントのモデル版とは限らない。

部品除去は同じ学習済みモデルに対する推論側の比較で、別アーキテクチャの再学習ではない。
物の区別を外すと同じ種類の親が複数あるときに参照不能、親関係を外すと派生物の由来が
不明になる。その質量をunknownとして残す。複数手を外す場合は一手だけ展開し、
要求された長いhorizonで不足する辺や到達を採点する。F02の独立した一手基準とは別物。

全方式は同じCPU環境・資源上限で実行するが、パラメータ数を等しくした実験ではない。
部品除去の学習費用は共有元モデルと同じ値を表示し、追加学習をしたように見せない。
[一次文献との関係](../研究/将来経路予測の先行研究比較.md)は著者概要の確認範囲に限定する。
ProbGuard等の著者実装を再現した比較や、網羅的な新規性の証明は行っていない。

## 集計と区間

- 行の識別子、正解、重み、課題群が一致した行だけを対応させる。対応しない行と棄権は
  omitted_rowsとして残し、異なる部分集合の平均をそのまま引かない。
- 行の差を分岐重みで課題群内平均した後、課題群を等重みにする。bootstrapは課題群単位。
  課題群が1つなら区間を算出しない。2群で区間を計算できても最終試料数の条件は別に必要。
- 正常課題はどれかの分岐で警報があれば偽警報1群。欠測予測に正しい負例の加点をしない。
  正例課題は既知の正例分岐すべてを先行検知した場合だけ検知1群とする保守的な集計。
  正例での棄権は見逃しとして数える。正解不明の課題群は別集計。
- 二項比率の片側exact上限/下限を報告。閾値を選べなかった場合は性能を0などと
  推測せず、missing_calibration_thresholdとして率と区間を未算出にする。
- 部品の寄与は、対応した正例群で先行検知が改善し、対応した正常群で偽警報が増えない
  ことを調べる。必要な対応・閾値・区間が欠ければ寄与は未判定。

採用判定は凍結したF02の数値条件を全て調べ、不明/試料不足と性能条件の未達を分ける。
評価用partitionの名前だけでは未使用を証明できず、別root IDだけでも独立性は証明できない。
現在のschemaでは生成エージェントのモデル比較も未記録のため、それらを合格と推定しない。
計算上全条件を満たす判定でも、製品有効化の承認にはならない。
