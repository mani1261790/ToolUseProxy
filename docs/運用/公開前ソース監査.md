# 公開前ソース・Git履歴監査

private repositoryをpublicへ変更すると、現在のHEADだけでなく、公開refから到達できる過去commit、tag、削除済みfileも参照可能になります。ToolUseProxyではrelease artifact監査とは別に、次のaggregate-only gateを実行します。

```bash
python3.11 scripts/audit_public_source.py --require-clean
```

## 検査範囲

- `git rev-list --objects --all`から到達できるunique blobと全path binding
- 全reachable commit messageとannotated tag message
- indexへ登録済みfileと、ignoreされていないworktree file
- `.env*`、DB、SQLite、秘密鍵・keystore、credential用途の危険なfilename
- GitHub / OpenAI / AWS / Slack / Stripe / Googleの高confidence credential形式、private-key header、password入りdatabase URL
- 2 MiBを超えるblob、未知binary、非regular worktree file

PDFとPNGは2 MiB以下かつ拡張子に対応するmagic bytesを持つ場合だけ既知のpublic binaryとして許可します。home directoryのabsolute pathは自動でsecretと断定せず、件数だけを人手privacy review用のobservationへ残します。明示的に固定したsynthetic credentialは検知回帰fixtureとして数だけ記録し、実credentialの一般allowlistにはしません。

## 出力とprivacy

stdoutはcommit数、blob数、scan byte数、finding category別件数、observation件数だけを含みます。credential値、file path、blob SHA、commit SHA、absolute repository pathは出力しません。`report_publishable: true`は監査reportが共有可能という意味であり、repositoryの公開承認ではありません。findingが1件でもあれば`status: failed`と終了code 1を返します。

失敗時はaggregate reportを成功扱いにせず、local環境で対象を特定し、credentialなら先に失効・rotationします。公開refから到達する履歴の書換えやforce-pushは破壊的操作なので、このcheckerは自動実行しません。

## 限界

- 形式を持たない任意のpassword、機密文書の意味、画像内文字を完全検出しない
- unreachable / dangling Git object、fork、外部backup、既存release assetは対象外
- Git LFS pointerはtextとして検査するが、外部LFS object本体の内容を取得しない
- secretが過去に漏えいしていないことや、既存credentialがrotation済みであることを証明しない

したがって、このgateは人手security / privacy reviewを置き換えません。LICENSE、manual Phase B、少人数pilot、公開承認とともに[#19](https://github.com/mani1261790/ToolUseProxy/issues/19)の外部gateとして扱います。
