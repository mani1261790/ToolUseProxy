# 将来予測の実行接続（#137・#138）

予測精度の証明（#204）と、機能の接続を分ける。今回の接続は、実イベント形式の入力、
Hook外の推論、実行前の追加停止、その記録を一続きにする。通常のPluginは無効のまま。
この文書の追加は有効化や実機受入を意味しない。

## 実装した経路

1. 既存のPreToolUseが呼び出しをevents.dbへ保存し、既存の保護判定を行う。
2. 明示設定されたprojectだけ、forecast.dbへ構造と入力版を予約する。
3. 別途起動したworkerが実行済みの操作を予測入力へ変換し、指定されたモデルで推論する。
4. recordモードは結果を待たず、既存の判定を返す。stopモードは最大100msだけ結果を待つ。
5. 同じproject・session・操作・入力・保護設定・通常設定・予測設定世代・モデル・期限に
   一致する確定結果だけを追加停止に使う。最終消費は一回限りで、無効化との競合も照合する。
6. 追加停止は既存ビュワーの「ブロック判定のみ」にも出る。詳細に
   「将来予測による追加停止（試験機能）」と表示し、未検証であることを示す。

既存denyは先に返し、予測から許可や本文変更を作らない。ToolUseProxyの正規管理操作を
追加停止の対象にしない。設定なし、worker不在、DB故障、期限切れ、未知の予測では
予測の追加停止を行わず、既存判定をそのまま返す。
100msは結果待ちだけの上限であり、SQLite操作と構造確認の時間は別。DBの待機時間と
問い合わせにも上限がある。実Mac/Codexの追加負荷は別途測定する。

## 人工環境で起動する

すべて人工データ専用のevents.dbとモデルを指定する。この作業では実利用DBを使わない。
モデルJSONは既存の `research.flow_forecast.artifacts.save_model` 形式とする。
モデルはworkerの起動時に読み込み、内容digestを固定する。ファイルを書き換えても
稼働中のモデルは切り替わらない。変更時は明示的に設定し直してworkerを再起動する。

```sh
python -m tooluseproxy.forecast_cli --events-db PATH/events.db init
python -m tooluseproxy.forecast_cli --events-db PATH/events.db configure --workspace WORKSPACE_ID --mode record --model-digest MODEL_SHA256
python -m tooluseproxy.forecast_cli --events-db PATH/events.db worker --model PATH/model.json --seconds 300
python -m tooluseproxy.forecast_cli --events-db PATH/events.db history --workspace WORKSPACE_ID
```

workerは別端末で動かす明示的な操作。Hookはworkerを自動起動しない。
追加停止の人工試験はconfigureのmodeをstopにする。offに戻すと進行中の結果も無効になる。
この設定は追加機能専用で、既存の保護・Unsetup承認・Plugin有効化を変更しない。
管理者による停止中はconfigureとworkerの入力処理を行わない。

Hookと設定CLIは配布物に含まれる。推論workerは研究コードと既存モデルを使う任意の
source checkout機能であり、通常のPlugin配布物には研究コードを同梱しない。
設定操作だけではモデルもworkerも導入されない。配布物単体ではworkerコマンドは
エラーを返す。この導入形態の製品化は別の作業である。

## 入力と未対応範囲

- 生I/Oは新しい予測キューへコピーしない。既存DBの行をローカルでhash照合する。
  ファイルパスは字句的な識別用hashにする。イベントの参照先ファイルは読まない。
- 予測入力は現在の候補操作より前にある、PostToolUseで成功を記録した操作だけから作る。
  現在の候補、未来の結果、別project/session、検出器のblockを実行済み事実に混ぜない。
- 現在の構造変換は明示的なread/copyに対応。失敗、Post欠落、未対応のAPIや複雑な操作を
  推測で成功に変換せず、unsupportedを記録する。登録パスとの一致は構造上の仮説であり、
  実バイトの由来を証明しない。モデルの能力語彙も実際の利用可能ツールの保証ではない。
- セッションのイベントや各関連表は最大200行、全体2MiB、予測履歴は最大90操作。
  超過時は予測を使わない。途中を黙って切り捨てたり、別群へ分割したりしない。
- 予測予約は2秒で失効。キューは最大1000件で満杯を返し、自動削除・自動再試行しない。
  stopの待機を過ぎた結果は履歴に残っても、その呼び出しの停止へ遡って適用しない。
- forecast.dbは信頼された人間だけの承認境界ではない。既存保護の解除権限を与えない。

## 確認と残件

人工DBを実Hook入口へ入力し、実際の予測コードとworkerから追加denyが返ること、
別プロセスでのモデル読込、入力変更・別セッション・モデル違い・期限・DB故障・
無効化・結果再利用拒否を試験する。正例は意図的に作ったfixtureモデルであり、
未知課題での精度や流出削減を示すものではない。

#137/#138の土台の接続と、#204の有効性、構造変換の対応拡大、worker配布、実機での
有効化・追加負荷・既存保護の確認を分けて追跡する。未完了の受入を理由に、
独立して実装可能な作業まで回答待ちにしない。
