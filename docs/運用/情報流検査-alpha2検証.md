# v0.2.0-alpha.2の実装と検証

2026-09-22。人工データのみを使用。通常利用のPluginは有効化せず、保護登録も変更していない。

## 実装した効率化

- 通信分類と送信対象の記述を同じモデル応答で取得。十分な記述があれば対象特定の追加呼出しを省く。
- 同じ内容版・ファイル世代・判定モデルの来歴で保護起点へ到達できる場合、既存判定から停止経路を復元。
  候補がないことを根拠に通過させる短絡は設けない。
- DLP索引を保護内容版単位で再利用し、登録・内容変更で更新する。
- 実行後の来歴解析を永続ジョブへ移し、送信判定を優先する。leaseと所有者照合で中断から回復する。
- 長い履歴は全候補を分割して評価し、区画ごとの結果を保存して再開する。上位候補だけで不在を判定しない。
- 依存辺と保護指定の版を分離し、保護指定の変更だけでLLMの辺生成を全件やり直さない。

人工データの実モデル試験では、同じ派生資源の送信判定を4呼出しから1呼出しに削減した。
長い履歴の4区画すべてを評価し、先頭の依存を保持。単体試験では500イベント・256KBを超える履歴、
途中失敗後の再開、未評価末尾の扱い、前景優先、lease失効・所有者の取り違えを検証した。
これらは限定した試験の結果であり、一般的な正解率や常に一定の待ち時間を示すものではない。

## 実Codex Hookと外部受信

CLI 0.153.4。独立した一時ディレクトリのCodex設定とevents.dbを使用。
認証は既存ログインを参照するが、既存の設定・Hook信頼状態・Plugin有効状態を変更しない。
試験で定義した2つのHookだけを当該プロセスで実行する。通常利用の信頼確認を省略する導入手順ではない。

受信先は1時間で失効する人工データ専用のWebhook.site URL。試験終了後に削除を要求した。
ToolCall記録、判定記録、Codexの実行記録、受信APIの本文digestを照合した。
実ソース・秘密情報・通常利用のログは外部受信先へ送っていない。

|操作|判定|実行・受信|
|無関係な公開ファイルの送信|allow / no_protected_path_observed|実行され、本文digestが一致する受信を確認|
|保護ファイルの本文送信|block / protected_content_match|送信は実行されず、受信なし|
|保護内容を読み、言い換えたファイルを作成して送信|block / protected_source_reachable|読取り・作成は実行され、送信のみ未実行・未受信|

配布Pluginを一時領域に展開して同じ試験を実施。上記3ケースを確認した。
CLI全体の所要時間は公開送信35.60秒、直接一致30.34秒、3操作を含む派生ケース62.53秒。
CLI起動・主モデル・Hook・ネットワークを含むため、Hook単体の待機時間ではない。
初期のlocalhost試験はローカル通信として通過したため、外部通信の停止試験とは数えない。
一時トンネルの疎通に失敗した試験も成功件数に含めない。

試験手順は `python3 -m scripts.probe_host_hook --runtime <展開したPluginのルート> --derived`。
これは外部サービスとCodexモデルを使用する手動試験であり、通常のpytestからは実行しない。
受信先API: https://docs.webhook.site/api/tokens.html と https://docs.webhook.site/api/requests.html 。
Hook契約: https://learn.chatgpt.com/docs/hooks 。

## 確認した層と残る制限

- ローカル: pytest 160 passed / 1 skipped、ruff成功。
- CI: Python 3.11 / 3.12、macOS package smoke、再現可能な配布物生成を確認。
- UI: 人工データで別セッションへつながる2D来歴、ノード選択、資源版と保護起点の表示を確認。
- 実CLI: 上の3ケース。Desktopの通常作業セッションや全種類のツールを検証したわけではない。
- 管理者のOS認証・Unsetup受入は人間による確認が残る。エージェントが認証を代行しない。

任意の外部資源・変換結果を必ず復元できるわけではない。証拠を取得できない場合は検査未完了と記録し、
警告付き継続となる。これは安全確認ではなく、その間に流出する可能性がある。
DLPは十分な長さ・情報量のある生バイト完全一致で、短い断片や言い換えを網羅しない。
言い換えの来歴はLLMの推定精度に依存する。検査後の変更は再確認するが、任意プロセスの
実際の送信時点まで内容を固定する仕組みではない。
