### P0: sink-first検査とlineageの有効性を比較する

担当Issue: [#36](https://github.com/mani1261790/ToolUseProxy/issues/36)

最初に、次の4方式を同じversioned corpusとpolicy条件で比較します。

1. sink tool inputへのdirect lexical comparison
2. sink固有adapterで解決した実payloadへのtyped comparison
3. local semantic comparisonをobserve-onlyで追加
4. semantic / resolved payloadへlineage evidenceを追加

評価は `Source × Transformation × Boundary × Sink` で整理し、credential、private prose、source code、Git diff、数値・判断材料を分けます。semantic similarityを因果関係の証明とは呼ばず、semantic-onlyの自動blockは独立validationと人間評価を通るまで有効にしません。

### P1: 実network egressでadapter coverageを測る

担当Issue: [#54](https://github.com/mani1261790/ToolUseProxy/issues/54)

Bash adapterのexternal sink判定は既知command patternのallowlistであり、実network接続そのものの観測ではありません。Python / Node.js、raw socket、DNS、custom binary、wrapper経由の偽陰性があり得ますが、現在は実network attemptの分母がないため率を測れていません。

最初はblockを変えず、value-freeな低レイヤー観測とadapter分類をsynthetic corpusで突き合わせます。ここでは「接続をexternalと分類できたか」というexternality recallと、「protected内容を検知できたか」というleakage recallを分離します。TLS payloadとMCP内部はlocal process観測だけでは見えないため、unknownとして残します。hosted Web Searchは現行CodexのPreToolUse / PostToolUse Hookへ現れず、ToolUseProxyの実行前遮断対象外として別に記録します。

### P2: AuditログからMLとrule候補を安全に育てる

担当Issue: [#55](https://github.com/mani1261790/ToolUseProxy/issues/55)

これは強化学習やonline self-learningではありません。値を含まないfeatureと人間labelを使い、active learning、クラスタリング、rule miningでreview順序と未知patternの発見を効率化します。allow eventの無作為sampleも残し、block候補だけを見るselection biasを避けます。

### P1: Similarity v2.1をadversarial評価する

担当Issue: [#20](https://github.com/mani1261790/ToolUseProxy/issues/20)

現profileは20文字以上・異なる英字10種類以上の値をdistinctive secretとして扱うため、`documentationreference`のような公開compoundもsource bindingで誤認し得ます。またartifact 50 / source 200のcandidate上限は意図したbounded heuristicであり、両rankingのquota外になる任意のadversarial集合までは保証しません。

1. 長い英字の公開compoundをnegative corpusへ追加する
2. alpha-only secret positiveと同じ形式のhard positiveを維持する
3. global thresholdを安易に緩めず、selectorやsecurity fieldなどsource-binding固有のsignalを比較する
4. 1,000〜10,000候補の生成poolでrecall、saturation率、SQLite parity、p95 latencyを測る
5. developmentで案を固定し、validationとrepository外holdoutを最後に評価する
