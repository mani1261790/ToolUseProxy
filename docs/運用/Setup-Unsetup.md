# SetupとUnsetup

Setupは初回のデータ送信への同意後、記録開始境界を保存する。過去のToolCallを取り込まない。
`setup --protect private.txt --protect notes.txt`で指定済みのファイルを一度に登録できる。
初期化済みなら同意・モデル・開始時点を維持する。ファイル登録失敗時は個別の結果を返す。
ログ画面の失敗を初期化の失敗と混同しない。

`unsetup open`はmacOSの管理者認証を経て、管理者用ツールの対象確認ダイアログを開く。
対象プロジェクトを停止し、登録とログを保持する。ほかのプロジェクトは変更しない。
管理者ツールが未導入・未登録の場合は完了にならない。

## 管理者側の事前導入

配布物の `tooluseproxy-authority-admin.py` を検証した管理者が、
`/Library/Application Support/ToolUseProxy/Admin/authority-admin.py` に導入する。
ディレクトリはroot所有で一般ユーザー書込み不可、スクリプトはroot所有・0444とする。
実行環境は `/usr/bin/python3 -I -S`。管理者側から `enroll --uid <利用者UID>
--workspace <対象の絶対パス> --data-dir <専用データの絶対パス>` を実行して対象を登録する。
本アプリはこの初回導入・登録を自動実行しない。旧版管理者ツールはGUI対応版への更新が必要。

## 権限の条件

確認ダイアログは認証ではない。OS認証とroot所有の管理状態を使用する。
Codexのユーザーが管理者権限を取得できる、認証操作を自動化できる、またはHookを任意に外せる環境では、
エージェントによる保護解除を完全には防げない。独立した管理者アカウント・エージェントへの昇格拒否が必要。
パスワードや確認操作をエージェントに委任しない。現行のユーザー所有設定全体をOSで強制保護する製品ではない。

`deactivating`は実行中処理の終了待ち。管理者用ツールの`finish`で再確認できる。
実環境のOS認証・停止受入は、人間による確認を別途行う。

### 来歴解析と状態確認

新規Setupの同意は、ToolCallのI/O・検査に必要なローカル資源の証拠を判定モデルへ渡すことと、
バックグラウンドの来歴解析によるモデル利用を含みます。保護登録時に送信試験は実施しません。
既存の設定を再Setupしても、バックグラウンド解析を勝手に追加しません。

`tooluseproxy analyze status --workspace /absolute/project` で解析ジョブの件数を確認できます。
`tooluseproxy analyze run --workspace /absolute/project` は有効な設定・管理状態を確認して、
待ちジョブを最大32件処理します。解析の再開は保護解除ではありません。失敗したジョブは
無限再試行せず残します。送信前の解析はバックグラウンドの成否と独立して必要な来歴を確認します。
`doctor` は管理者用ツールの配置・所有権・書込み権限も確認しますが、OS認証の成功や
実Hookの稼働を証明するものではありません。

ログの呼び出し詳細から「来歴グラフを見る」で別画面を開けます。最大200ノード・400辺の
祖先範囲を、判断時の版で表示します。本文は表示せず、読取り／書込みの対象、資源版、
セッション、解析の未完了を確認できます。表示上限による省略は明示します。
通信が切れても、保護機能が解除されたという意味ではありません。
