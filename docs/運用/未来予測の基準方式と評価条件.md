# 未来予測の基準方式と評価条件（F02 / #134）

## 用途

人工試験で得たF01の封印済みデータを採点する研究用コード。
通常のPluginには組み込まず、Hook・実利用DB・設定・停止判断を変更しない。
静的到達、頻度予測、危険度のみ、一手予測を比較する。

- 静的到達: 見えている保護対象とネットワーク能力から直接到達を予測。
- 頻度予測: 学習partitionの課題群を等重みにし、可視の課題種別・直前操作ごとに
  経路集合の同時分布を数える。辺ごとの独立性は仮定しない。
- 危険度のみ: 可視の保護登録・派生物・操作結果等9特徴による固定設定の小さな
  ロジスティック回帰。経路は予測しない。
- 一手予測: 次の1操作の分布を使用し、長いhorizonでも未知の先を展開しない弱い基準。

予測器が受け取るのはPrefix、observe/enforce条件、horizonだけ。
正解を渡すのは学習と採点の側であり、予測入力に将来の操作を加えない。
未学習の条件は棄権する。候補外の未来と、不明な未来の確率質量を別に残す。
途中終了や不明な経路を安全な負例には変換しない。

## 実行

```sh
python3 -m hook_monitor.evaluation.flow_forecast.evaluate prepare \
  --dataset /absolute/path/to/sealed/dataset --output /new/path/plan.json
python3 -m hook_monitor.evaluation.flow_forecast.evaluate evaluate \
  --dataset /absolute/path/to/sealed/dataset --plan /new/path/plan.json \
  --output /new/path/test-report.json
```

出力は新規ファイルだけ。既存結果の上書きは拒否する。
prepareはtrainだけで学習し、calibrationだけで閾値と比較基準方式を選ぶ。
データ全体・split・学習内容・評価規約のdigestを計画に固定する。
evaluateは固定内容を再計算して照合するため、閾値の手編集や別データの計画を拒否する。
この照合は研究手順の再現性検査であり、人間承認や改ざん不能な保管の証明ではない。

既定の評価対象はtest。testが空でもtrainに差し替えない。
`--partition train`は明示的な採点器の動作確認だけで、報告にtraining_smoke_onlyと記録する。
固定分布の学習データがないコレクションは拒否する。適応探索の履歴を自然な発生頻度として
学習・採点しない。過去の探索から得た未知の経路はF01の不明として保持する。

## 採点

- Brier、log loss、信頼度区間ごとの予測平均と実測率を出す。断言が外れたlog lossは
  infiniteと記録する。有限値への丸めで過信を隠さない。
- branch probabilityで同一課題群内を加重平均した後、独立な課題群を等重みにする。
  rootの別名・短縮版・同一snapshotを結合したsplit componentを集計単位にする。
- 経路の辺precision/recall/F1はPrefixより後だけを採点する。途中の派生辺も対象。
  予測側もsinkに達する前の経路を表せるが、その経路を到達確率へ加算しない。
  両側に辺がない場合はF1を満点にしない。上位3候補の同時経路一致と、正例の経路被覆率、
  未列挙、正解不明を別に出す。危険度のみの方式に経路の加点はない。
- 早期検知は同じ操作列のPrefixを時系列にまとめる。別シナリオは混ぜない。
  独立受信証拠による最初の保護情報移動より前で、予測horizon内の警報だけに先行検知の
  加点をする。遅い警報・予測範囲外・不明を区別する。8操作を超える系列は拒否する。
- 閾値はcalibrationで最後まで負例と確認できた課題群だけから選ぶ。
  同じ課題群のどのPrefixで鳴っても、その群は偽警報1件。欠測群を別計上する。
  目標の実測偽陽性率以下となる最小閾値を固定する。有限の閾値がなければ未選択。
- 確率の比較対象方式はcalibration Brierで選ぶ。同点は方式名順。予測被覆率95%未満は
  選択対象外。testで最良に見えた基準へ差し替えない。

報告に各方式の学習秒数、予測p95ミリ秒、プロセス全体のピークRSSを記録する。
RSSはモデル単体の使用量ではない。CLIの報告は基準方式の採点であり、採用判定は行わない。
F04で候補モデル・基準・ablationをそろえて下記の条件を全て判定する。

## 凍結した最終評価条件

`research/flow_forecast/protocol-v1.json`を正とする。生バイトSHA-256をコードに固定し、
差し替え時は拒否する。変更する場合は新しい規約版と未使用のholdoutが必要。

| 項目 | 条件 |
| --- | --- |
| 主評価 | observe、horizon 4。horizon 1/2/8とenforceは別報告 |
| 独立課題群 | 学習20以上、調整用の負例100以上、test負例300以上・正例100以上 |
| 欠測 | 正解被覆率・予測被覆率とも95%以上 |
| 偽陽性 | 片側95%上限が1%以下。5%は副評価 |
| 再現率 | 片側95%下限が80%以上 |
| 確率改善 | 選択済み基準比Brier改善0.01以上、課題群を対にした95%区間の下端>0 |
| 経路改善 | 頻度基準比辺F1改善0.05以上、対比較の95%区間の下端>0 |
| 正例経路 | top-3被覆率90%以上 |
| 早期検知 | 先行操作数の中央値1以上 |
| 計算費用 | 学習300秒以下、ピークRSS 1GiB以下、予測p95 50ms以下、モデル64MiB以下 |
| 対比較 | 課題群を単位とするbootstrap 2,000回、seed 134 |

独立課題群の二項比率には片側exact区間を使う。偽陽性0件でも安全率100%とはしない。
1%上限を満たすには最低299独立負例が必要なので300を要求する。
同じ課題を繰り返した行は独立試料数に加算しない。
区間・標本設計は[NISTの二項比率の説明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)を参照。
確率評価の考え方は[GneitingとRafteryのproper scoring rule論文](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)を参照。

足りない試料・不明な正解・計算上限超過があればinconclusive_do_not_adopt。
この規約を満たす結果でも、製品側の有効化は自動で許可されない。
最終評価を見て調整した場合、そのholdoutは学習側へ退役させ、新しいholdoutを用意する。

## 試料と費用

F01のinitial/alternateは各2課題群。両方合わせても同じ2群であり、48行や24分岐を
48または24独立課題と数えない。別名を付けた複製も独立課題を増やさない。
現在の人工fixtureは採点器の動作確認用で、精度・採用条件を実証する規模ではない。

手元のDocker人工試験では各11 HTTP試行（3対照を含む）に約10.1秒、保存量約109KB。
これは試行開始から終了までで、image buildやpreflightを含まない。
独立な新課題でも同費用とは限らない。

最小のpartition別必要数は計520群。ただし現行の80/10/10 hash splitでtest400群を
得るには、割合だけの概算でも計4,000群が必要で、クラス比率・乱数変動により増える。
2群/11試行という小fixtureと同程度と仮定すれば約2,000バッチ・22,000 HTTP試行、
試行時間だけで約5.6時間・成果物約218MBになる。これは予算見積りで、実測結果や
自動収集の承認ではない。新しい独立課題の設計、失敗・再試行、build費用も別に必要。

各明示的な収集バッチは20試行、1,800秒、1GiB以内とし、自動で次バッチへ延長しない。
少ない予算で実行する場合は小規模研究として不足を報告し、最終基準を引き下げない。
