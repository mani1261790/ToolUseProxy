# GitHubでの研究進捗管理

このプロジェクトでは、研究概要、作業項目、週次報告を次のように分けて管理します。

## README

研究の背景、目的、3段階のロードマップ、現在地を掲載します。週ごとの詳細な報告は追記しません。

## Issues

調査、実装、実験、文書化など、完了条件を持つ作業をIssueとして管理します。

次に実装する内容のまとまりは [実装タスク.md](実装タスク.md) に整理し、そこから必要に応じてIssueへ切り出します。READMEには研究全体の方向性だけを置き、細かい実装タスクはdocsとIssueで管理します。

毎週の進捗報告も1週間につき1件のIssueとして作成し、`weekly-report`ラベルを付けます。Issue作成時は「週次進捗報告」テンプレートを使用します。

週次報告には次の内容を記録します。

- 今週の目標
- 実施したこと
- 分かったこと
- Pull Request、Commit、文書、実験ログなどの成果物
- 問題・未解決事項
- 来週やること
- 達成 / 一部達成 / 未達の判定

報告と確認が終わった週次IssueはCloseします。Close後も履歴、コメント、関連リンクは残ります。

## GitHub Project

ProjectはIssueとPull Requestの進行状況を一覧するために使用します。週次報告の本文を置く場所ではありません。

次のフィールドを使用します。

| フィールド | 用途 |
| --- | --- |
| Status | `Todo`、`In Progress`、`Done` |
| Stage | `1: Trace`、`2: Detect`、`3: Stop` |
| Type | `Research`、`Implementation`、`Evaluation`、`Documentation` |

`Stage`はTrace / Detect / Stopという研究上の由来を示します。複数Stageを横断するpackage、配布、導入UXは無理にStageを追加せず、`productization`ラベルとrelease milestoneで管理します。`v0.1.0 Public Alpha` milestoneはalpha.12の公開で完了しました。現在は[`Detection Quality`](https://github.com/mani1261790/ToolUseProxy/milestone/2)で、実project pilotと検出精度改善を管理します。

現在のIn Progressは、実project pilotの[#99](https://github.com/mani1261790/ToolUseProxy/issues/99)と、比較評価の中心Issue [#36](https://github.com/mani1261790/ToolUseProxy/issues/36)です。Codex対応の完了作業と、ToolUseProxy本体の検出精度改善を同じIn Progressへ混ぜません。

現在は標準のTableビューで管理します。作業項目が増えた段階で、次のビューを追加します。

- `By Status`: Status別のボード
- `Research Roadmap`: Stage別に研究全体を確認する一覧

Projectの説明には現在の優先順位とfield運用だけを置きます。週次の詳細は週次Issueへ集約し、同じ内容をProjectへ重複保存しません。

## 毎週の流れ

1. 週の開始時に、今週着手するIssueを`In Progress`へ移す
2. 研究・実装を進め、CommitやPull Requestを対応するIssueへ関連付ける
3. 週末に週次進捗報告Issueを作成する
4. 週次IssueをProjectへ追加し、`Type: Documentation`、確認後に`Status: Done`としてCloseする
5. 完了したIssueを`Done`へ移し、次週の作業を決める
