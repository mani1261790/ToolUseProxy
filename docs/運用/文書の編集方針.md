# 公開文書の編集方針

[文書一覧](../索引.md)

本文、見出し、説明、操作案内は日本語で書きます。READMEから導入、仕組み、制限、データの扱い、非公開の報告まで、リンク先も日本語で読めるようにします。

コマンド、パス、API名、JSONのキー、状態コード、製品名、論文名などは、実装や出典と照合できる表記を残し、必要な説明を日本語で添えます。Apache-2.0のLICENSE原文は翻訳・改変しません。実験入力や生の出力など、内容のハッシュを検証する資料は文章校正で変えず、日本語の説明を別に置きます。

## 読む順序

READMEは目的と利用例、クイックスタートは最初の操作、設計文書は実装の処理順を説明します。索引から、利用手順・現行実装・検証・研究案・履歴へ移れるようにします。セキュリティ報告には非公開の窓口と記載する内容を明記します。

英語版READMEの旧URLは、日本語の正本への案内として残します。重複した仕様説明を維持しません。

## 現行仕様と履歴

現行仕様を書く際は、実装・配布版・検証条件を照合します。設計案、実装済み、配布済み、実Hookで確認済みを分けます。未判定や画面上の表示を、許可・遮断の実行結果と混同しません。

過去の資料は当時の意味を維持し、冒頭で旧版・検討記録と明示します。英語の説明は日本語に直せますが、過去の実験結果や入力データを現在の仕様に合わせて書き換えません。機械が扱う識別子とサンプルの構文も保持します。

## 変更時の確認

- 現行コードとアルゴリズムの説明が対応しているか。
- 保護の限界、モデルへのデータ送信、判定未完了時の実行状態が一致しているか。
- Markdownの相対リンクと見出しへの参照が到達できるか。
- Mermaidの図が描画でき、分岐と矢印の向きが説明と一致しているか。
- 付属Skillの翻訳で、操作範囲や承認条件が変わっていないか。

同じ説明を複数箇所で増やすより、詳しい正本へリンクします。版を固定した検証記録は検証時点として残し、READMEの公開状況と混ぜません。
