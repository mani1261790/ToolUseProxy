# 人工試験の再現・短縮・旧新版比較

Issue #131。#130が保存した操作列、または同じ閉じた形式のJSONを入力し、
新しいDocker環境で再現・短縮・旧新版比較まで実行する。常駐処理や実利用Hookを起動しない。

## 実行

```sh
python3 -m hook_monitor.evaluation.flow_lab.replay_runner \
  --before /absolute/path/to/old-checkout \
  --after /absolute/path/to/new-checkout \
  --search-directory /absolute/path/to/synthetic-search \
  --attempt 1 \
  --output-directory /absolute/path/to/new-comparison
```

`--search-directory`は#130の探索出力。`search.sqlite3`を読み取り専用で参照し、
1始まりのattemptの操作列だけを取り出す。探索の再開・モデル呼出しは行わない。

固定再生は`--search-directory`の代わりに`--case case.json`を指定する。

```json
{"actions":[{"source":"public","encoding":"plain"},{"source":"protected","encoding":"plain"}]}
```

sourceはpublic/protected/file、encodingはplain/base64。
representationとclientの省略時はliteral/urllib。#130と同じ検証を通すため、
任意のコマンド・接続先・ホスト上のファイルパスは操作列に含められない。

## 保存と再実行

- 出力先は専用の新規ディレクトリー。探索・実利用の保存先と共有しない。
- `search.sqlite3`に操作列・試験前の予約・全再試験結果・最終報告を保存する。
  `trials/`に各操作と対照試験の観測を保存する。未再現の試験も削除しない。
- 完了後に同じ引数で再実行しても新しい通信試験は行わず、保存した報告を返す。
- 報告保存前に中断しても、完了済みの試験を順に読み戻して処理を続ける。
  途中で実行結果が不明になった試験は`replay_requires_reconciliation`で停止し、
  同じ操作を勝手に再送しない。記録はpendingのまま保持する。
- 同じソース版の再現では最初のDockerイメージを固定する。イメージが消えた場合は
  勝手に再ビルドして同一環境と扱わない。試験ごとの受信先・ネットワークは新規。
- 制御実装、入力、旧新版のソース、予算が変わった保存先の再利用は拒否する。
- 最大5ケース、各ケースで公開受信・保護受信・保護停止の3対照＋対象1試行、
  合計最大20試行。各対象操作列は最大10操作。既定600秒、保存量1GiB。
  時間は各外部操作の前に確認し、実行中のDockerコマンドには個別タイムアウトがある。

## 短縮と原因の照合

最初に元の操作列を再現してから、1操作ずつ削る。
元と同じ失敗種別・失敗を起こした操作・判定根拠の指紋が残り、ソース・policy・
Dockerイメージが一致する場合だけ短縮を採用する。指紋はaction/severity/sink_type/
source_node_kind/reasonの構造化記録から作り、対応する本文も報告へ残す。
識別子や試行日時を問題の同一性に含めない。

これは現在の人工HTTP操作の判定根拠を照合する仕組みであり、任意のプログラムの
因果関係を証明するものではない。現在の各guardは新しい状態から起動するため、
履歴に依存する一般的なファイル操作列の再現は対象外。
根拠が取れない場合はcause_unverified、再現しなければnot_reproducedとして元を残す。
短縮予算に達した場合も、それまでの候補と全試験を保持する。

## 比較結果

同じ操作列と環境プロフィールを比較する。受信対照の失敗や観測不足はinconclusive。
公開操作が実際に成功して受信され、保護データの停止対照も通った場合だけimprovedを認める。
単に拒否が消えた、receiverが故障した、保護を全許可にした、という変更は改善ではない。
元の問題が再現しなければ、後段で見えなくなっても修正の証明にはしない。

`regression_candidate`には短縮した操作列・元の失敗・期待結果を保存する。
恒久試験への採用はcandidate_not_promotedと明示する。候補のactionsを固定再生に使用できる。
Issueへの連携は#132で接続し、本番反映は行わない。
