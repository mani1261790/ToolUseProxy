# 現行の研究方針

[紹介](../../README.md) · [現行アルゴリズム](../設計/エッジ生成と送信判定.md) · [文書一覧](../索引.md)

## 解きたい問題

利用者が登録した秘密情報そのものと、それに由来する内容が外部へ送られそうなら止める。一方、同じ作業中でも無関係な内容の送信は通す。この区別を、Codexから得られるToolCallの記録を使って行います。

単語が似ていることと、情報を引き継いだことは同じではありません。秘密のメモを手順書に書き換えたり、数値を集計したりすると、元の表現が残らなくても情報は伝わります。逆に、先に秘密を読んだという理由だけで、その後のすべての出力を秘密由来にすると通常の作業を妨げます。

## 現行の構成

観測できた資源の版や操作の契約は機械的に扱い、変換・生成した内容の依存関係はモデルが推定します。送信時には、現在の保護指定に対応する読取り属性へ到達するかを機械的に調べます。送信内容との完全一致を検査するDLPも独立して併用します。

グラフは推定と観測の記録です。経路を説明できることは、エッジの意味がすべて正しいという証明ではありません。モデルには最終的な許可・遮断を決めさせず、根拠と参照した出力範囲を残します。

## 何を評価するか

- 原文の直接送信と、要約・翻訳・計算・コード化などを経た送信を検出できるか。
- 秘密を読んだ後の独立した出力や、混在した出力の無関係な部分を誤って止めないか。
- 上書き、名前変更、同じ内容の別ファイル、別セッションの生成元を取り違えないか。
- 送信本文だけでなく、宛先や選択結果を通じた情報の継承を扱えるか。
- 判定の往復回数、入力量、再利用率、実行前の待ち時間を減らせるか。
- 証拠不足、モデル障害、期限超過によって、正当な作業を意図せず保留しないか。

検出率だけでなく、誤検出、判定未完了、実際に送られたかどうか、待ち時間を分けて測ります。合成データの正解率を実利用全体の保証へ置き換えません。

## 確認済みと未完了を分ける

alpha.16では、原文・派生手順書・独立した受付案内の3種類を実DesktopからGitHubへ送るリハーサルを行い、前2件の遮断と案内だけの送信を確認しました。[検証記録](../運用/alpha16検証.md)は条件付きの1回の受入結果です。

長い履歴の候補選択や局所的な情報継承判定は、[増分情報継承グラフの設計案](../設計/増分情報継承グラフ.md)と[先行研究調査](../調査/2026-09-24-依存エッジ生成の先行研究.md)で扱います。直近の件数だけで切り詰め、候補がないことを安全の根拠にする方式は採用していません。候補検索の試作と製品への統合を区別します。

現在の実装には有限の期限と、判定未完了で実行を保留する経路が残ります。この問題は[判定完了と復旧](../設計/判定完了と復旧.md)で追跡します。将来予測・早期停止の研究コードは、通常の送信判定には接続しません。

## 範囲外

OS全体の通信監視、LLM内部の完全な情報流追跡、Hookに届かない操作の遮断、任意のプログラムに対する完全な因果関係の復元は保証しません。モデルに渡す情報と保存されるデータについては[プライバシー](../../PRIVACY.md)、製品の境界は[対応範囲](../../SUPPORT.md)を参照してください。

v0.1の類似度中心の構成と実験結果は[旧研究方針](../history/v0.1/研究方針.md)に保存しています。
