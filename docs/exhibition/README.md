# ToolUseProxy リアルタイムログビューアー

ToolUseProxyが実際に保存している `events.db` を読み取り専用で開き、
ToolCall、保存された入力・出力、ブロック等の判定を1秒ごとに表示する。
人工シナリオの再生画面ではない。Pluginの有効化、Hook実行、DB移行・変更は行わない。

リポジトリのルートから、利用中のDBを指定して起動する。

```sh
python3 -m scripts.serve_exhibition --db /absolute/path/to/events.db
```

表示された `http://127.0.0.1:…/…/` をブラウザーで開く。終了はCtrl+C。
DBはToolUseProxyの `--db` / `TOOLUSEPROXY_DB_PATH`、data-dir、Pluginの
`PLUGIN_DATA` に応じて異なるため、閲覧したい保存先を明示する。
HTMLファイルを直接開く方式ではなく、ローカルサーバーを使用する。

- 左側に最新300イベント内のToolCall、右側に呼び出しの入力・出力・判定を表示。
- 新しい呼び出しを自動選択。過去の行を選ぶと自動選択を解除し、その呼び出しの
  遅れて記録された出力・判定を引き続き更新する。チェックを戻すと最新を追う。
- 同じworkspace・session・tool_use_idのPre/Postをまとめる。
  sessionやcall IDが欠ける場合はイベント単位とし、別呼び出しを推測で混ぜない。
- `policy_decisions` と `sink_candidates.metadata_json.event_id` を結び付けて
  保存された判定を表示する。「ブロック判定」は判定記録であり、外部受信先の
  不達証明ではない。判定未記録を許可とは表示しない。
- 入力・出力が保存されていなければ「未記録」。既存のマスク処理を逆転したり、
  transcriptや参照ファイルから未保存の内容を補完したりしない。
- I/Oは選択した呼び出しだけ取得し、最大50イベント、各payload先頭128K文字に制限。
  切り詰めは明示する。一覧は新規保存順で、全履歴の検索・書き出しは対象外。
- 接続失敗は画面に表示し、自動再接続。既存表示は最後に取得できた記録として残る。
- ToolUseProxyが無効ならDBの過去記録を表示して待機する。ビューアーが収集を開始する
  わけではない。稼働中のToolUseProxyが同じDBへ追記すれば、画面が自動更新される。

サーバーはloopbackだけで待ち受け、起動ごとにランダムURLを発行する。
Host/Origin検査、外部リソース禁止、キャッシュ禁止を適用し、任意ファイルの配信はしない。
保存されたI/Oには機密情報を含み得るため、画面やURLの共有対象には注意する。
元の人工再生データ生成器は独立した試験補助として残るが、この画面では読み込まない。

検証: 実DBと同じEventStoreスキーマの人工DBへPre/Post/判定を後から保存し、
表示の更新、session分離、読み取り専用、切り詰め、接続断復帰、HTTP境界を試験する。
Pluginを有効化した実機Hookの収集確認とは区別する。

## 読みやすさ

入力・出力は項目別に表示し、コマンド・標準出力・エラー出力・終了コードなどの
既知の項目には日本語の見出しを付ける。文字列内の改行はそのまま表示し、
空文字と未記録を区別する。未知の項目も省略せず、元の項目名で表示する。
ブロック判定は一覧と詳細の両方で文字と色で示す。実行後の記録があることを
成功や許可とは表示しない。内部ID・元のJSON・DBパスは折りたたんで参照する。
時刻はブラウザーの現地時刻で表示する（SQLiteの標準UTC時刻を変換）。

## プロジェクト・セッション別の表示

ヘッダーの「表示・絞り込み」からプロジェクトとセッションを選択できる。「ブロック判定のみ」は
選択した範囲内で組み合わせて使える。全体表示の各行にも所属を表示する。
IDが同じでも別プロジェクトのセッションや呼び出しを混ぜない。IDが未記録の
ログは「未記録」として選択でき、実際に同一セッションだったとは推定しない。

絞り込みはDBの取得時に適用し、その条件内で最新300イベントまでを表示する。
ブロックのPreが表示範囲外でも、同じ呼び出しに対応するPostをブロック対象として
表示する。セッション候補は全イベントの所属から取得し、最新1000組まで。
上限を超えた場合は画面に明示し、選択済みの条件は自動で解除しない。
条件変更時には前の詳細を消し、切替え前の遅い応答は表示へ反映しない。
最新追従は選択した条件の範囲内で行う。

表示設定はポップアップ内にまとめ、通常は高さ48pxのヘッダー直下からログを表示する。
最新追従の切替えと接続先DBも同じポップアップにある。Escape・閉じるボタン・
背景クリックで閉じる。選択中の条件は下部に表示する。
呼び出し一覧と詳細は独立してスクロールできる。

プロジェクト・セッションの選択メニューとチェックボックスは画面共通の外観にする。
メニューは矢印キー/Home/Endで候補移動、Enter/Spaceで決定、文字入力で先頭一致を
移動、Escapeで候補だけを閉じ、Tabで次の操作へ移る。チェックボックスはネイティブの
操作・読み上げ状態を保ち、外観のみ独自描画する。一覧件数は「〇件」と表示し、
最新追従の説明は設定ポップアップ内に集約する。

## 初期化・設定と現在の稼働を区別する

候補はログが保存されたプロジェクトであり、現在の保護対象一覧ではない。
プロジェクトまたはセッションを選び、表示設定の「プロジェクトの状態」を開くと、
このDBの初期化操作による登録記録と利用設定の保存有無を別々に確認できる。
`init`/`setup_profile`による登録記録を確認できない場合も、未初期化と断定しない。
設定行が存在することは、必要な設定がすべて有効であることを意味しない。

保護対象リストやactivationファイルを読むことなく、既存DBの登録情報だけを参照する。
保護対象の登録状況と現在のPlugin/Hook稼働は未確認として表示し、ログ・設定の存在を
「保護中」へ読み替えない。ヘッダーの接続表示もビューアーとログDBの接続状態である。

## 将来予測の追加停止

同じ保存先に任意機能の `forecast.db` がある場合、実際にHookで停止判定へ適用した
記録だけを読み取り専用で追加表示する。予測が高いだけの結果、recordモード、待機時間を
過ぎた結果をブロック扱いにしない。詳細では試験機能であることを説明する。
予測設定をoffに戻しても過去の停止記録は残す。表示は有効化操作ではない。

展示の主画面の候補は[展示の見せ方](展示の見せ方.md)に整理している。
