# 情報流グラフの可視化

この文書は、保存済みの `events.db` と `analysis_runs` から情報流グラフを確認する方法をまとめます。

可視化は2段階に分けます。

1. `trace_lineage.py`
   - treeコマンド風に経路を読むためのCLI
   - sourceから下流へ、または任意nodeからsourceへ経路を確認する
2. `export_graph.py`
   - Mermaid、Graphviz DOT、JSONとして外部出力するCLI
   - GitHub Issue、研究メモ、画像化に使う

## 前提

先にlineageを再構築します。

```bash
python3 scripts/rebuild_lineage.py \
  --db .tooluseproxy/events.db \
  --workspace-root "$PWD" \
  --rebuild-graph
```

以降は再構築結果に表示された`analysis_run_id`を`RUN_ID`へ設定した例です。代わりに`--workspace-root "$PWD" --latest`を使うと、そのworkspaceの最新completed offline runを選べます。global latestへのfallbackはありません。

この処理により、次のテーブルが更新されます。

- `information_flow_edges`
- `source_binding_edges`
- `lineage_assignments`
- `resource_versions`

## 経路を読む

最新の解析runの概要を見るには次を使います。

```bash
python3 scripts/trace_lineage.py --analysis-run "$RUN_ID"
```

sourceから下流nodeをtree風に表示します。

```bash
python3 scripts/trace_lineage.py --analysis-run "$RUN_ID" --source env_main
```

任意nodeがどのsource由来かを逆引きします。

```bash
python3 scripts/trace_lineage.py --analysis-run "$RUN_ID" --node "artifact_fragment:$FRAGMENT_ID"
```

詳細なedge理由まで見たい場合は `--verbose` を付けます。

```bash
python3 scripts/trace_lineage.py --analysis-run "$RUN_ID" --source env_main --verbose
```

## 図として出力する

MermaidはGitHub Markdownに貼りやすい形式です。

```bash
python3 scripts/export_graph.py --analysis-run "$RUN_ID" --format mermaid --source env_main
```

ファイルへ保存する場合は `--output` を使います。

```bash
python3 scripts/export_graph.py --analysis-run "$RUN_ID" --format mermaid --source env_main --output graph.mmd
```

Graphviz DOTは画像化に向いています。

```bash
python3 scripts/export_graph.py --analysis-run "$RUN_ID" --format dot --source env_main --output graph.dot
dot -Tpng graph.dot -o graph.png
```

JSONは後でHTMLビューアや分析スクリプトへ渡すための中間形式です。

```bash
python3 scripts/export_graph.py --analysis-run "$RUN_ID" --format json --source env_main
```

## 表示対象

デフォルトでは、指定したanalysis runの `lineage_assignments` に含まれるnodeと、その経路に使われたedgeだけを出力します。

全edgeを見たい場合は次を使います。

```bash
python3 scripts/export_graph.py --analysis-run "$RUN_ID" --format dot --all-edges
```

`--all-edges`は`rebuild_lineage.py`が作る`full` offline snapshotだけで使用できます。runtime session runはmutable scopeなので拒否されます。

`--all-edges` と `--source` を組み合わせた場合、そのsource lineage周辺のedgeだけを追加表示します。

```bash
python3 scripts/export_graph.py --analysis-run "$RUN_ID" --format dot --source env_main --all-edges
```

ただし、全edge表示はノイズが増えやすいため、通常は `--source` でlineageだけを見る方が読みやすいです。

本文previewを図に含めたくない場合は `--no-preview` を使います。

```bash
python3 scripts/export_graph.py --analysis-run "$RUN_ID" --format mermaid --source env_main --no-preview
```

## 表示ルール

- `protected_source`
  - 保護対象source
- `source_chunk`
  - sourceを比較単位へ分割したchunk
- `resource_version`
  - Filesystem adapterが再構成したファイルversion
- `artifact_fragment`
  - tool input / outputから抽出した比較単位

edge labelは次の形式です。

```text
relation/method score
```

例:

```text
read_from/filesystem_read 1.00
derived_from/substring 0.95
similar_to/shingle_jaccard 0.42
```

`trace_lineage.py --verbose` では、edgeの `evidence_level` と `reason` も確認できます。

## 現時点の制限

- Mermaid / DOTは静的な図であり、展開・折りたたみはできません
- 長いfragment本文はpreviewに切り詰めます
- source lineageがないanalysis runでは、summaryのみ表示されます
- 現在のsink表示はSearch、Bash、MCP adapter由来の `external_*` sink candidate に対応しています
- final answer のsink分類にも対応しています
