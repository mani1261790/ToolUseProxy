# 明示された送信を検査する境界

ToolUseProxyの判定対象は、ToolCallの仕様と入力に明示された外部送信とする。
スクリプトを起動するという理由だけで、その実装・import・子プロセスを探索しない。
ただし、入力中のインラインコードや複合コマンドに送信が書かれていれば対象となる。
localhostへの要求の先で行われる転送も、この境界では検査しない。
これはネットワーク隔離ではない。隠れた通信も制限するには別の実行制御が必要になる。

## 判定の順序

1. ToolCallを記録する。
   現在の保護登録が0件なら、この方針に対する検査を機械的に完了する。分類モデルや背景解析は起動しない。
   登録一覧の読み取り失敗は0件と区別する。結果は次の呼び出しへ使い回さず、毎回登録を確認する。
2. 入力に外部送信が明示されているか分類する。分類時に送信内容の詳細解析は行わない。
3. 明示された送信がなければ、グラフ解析の完了を待たずに通常の承認手順へ戻す。
4. 送信なら、送信内容の取得・DLP・依存グラフの検査を行う。
5. 現在の保護登録とグラフ上の資源を照合する。後段の依存推定で送信分類を上書きしない。

分類に失敗した場合は、外部送信だと断定して実装全体の探索を開始しない。
通信分類には低い推論予算を指定し、計算されたパスやループの展開は要求しない。
モデルの実行上限は60秒とする。上限は許可条件ではなく、失敗時は未完了のまま保持する。
失敗は未完了として記録する。未完了を許可にも流出検出にも変換しない。

## グラフと保護設定

依存エッジと資源の読み書き・版を保持し、保護登録は別の方針として照合する。
登録と解除は、同じグラフを使った次の判定に反映される。過去の判定記録は保持する。
記録以前の由来、モデルが見逃した依存関係を機械的探索で補完できるわけではない。

## 並行処理と再試行

グラフ解析のセッションロックは、記録・通信分類・ローカル操作には使わない。
グラフ更新同士は引き続き直列化する。外部送信は必要な解析を待つ。
証拠不足の判定は needs_evidence、背景ジョブは paused とし、同じ解析を自動反復しない。
新たな実行要求では再評価する。背景ジョブの処理回数を減らすのは優先度による中断だけとし、
予算不足などによる再試行が無限に続かないようにする。

## 検証の区別

ロック保持中のローカル処理、後からの保護登録・解除、再試行の停止は自動テストで検査する。
実モデルによる分類テストは架空のコマンド文字列だけを送信し、コマンド自体は実行しない。
それらはDesktopでの実Hook経由の操作完了を証明するものではない。
