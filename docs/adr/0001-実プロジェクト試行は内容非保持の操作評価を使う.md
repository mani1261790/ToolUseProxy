# 実プロジェクト試行は内容非保持の操作評価を使う

実プロジェクト試行では、既存の情報流記録を複製したり、保護対象の本文、命令文、URL、接続先、ファイルの場所を新しい評価用データへ保存したりしない。利用者の環境でToolUseProxyを有効にした全プロジェクトについて、外部送信の可能性を判定した全操作の時刻、プロジェクト、判定方式と設定の版、判定根拠、許可または停止、判断時間、利用者の停止確認を内容非保持の操作評価として継続保存し、利用者が明示的に削除するまで保持する。停止確認には3つの選択結果だけを保存し、自由記述は保存しない。後から訂正できるが以前の選択は消さず、訂正履歴を残して最新版だけを集計に使う。ToolUseProxyへ届かない操作は、作業後にCodexのローカルなタスク記録から種類と件数だけを確認し、内容は保存しない。同じ判定方式について比較可能な操作評価が20件以上あるプロジェクトが2つ以上になった時点で、該当する全プロジェクトを含む初回比較をタスク終了時に自動生成する。未確認停止は比較から外して件数を明記し、比較全体は保留しない。その後も比較対象となった各プロジェクトで比較可能な操作評価が20件ずつ増えるたびに継続比較を作り、20件未満のプロジェクトは待たず、判定方式の版が変わった場合は以前の件数と混ぜない。各試行結果からGitHubへ掲載可能な内容非保持の外部共有案をローカルで自動生成する。alpha.12以前の記録は集計処理の動作確認にだけ使い、新しい比較の件数へ含めない。問題原因は構造的な情報から自動で候補を分類し、材料が足りない場合は未特定とする。改善用の操作評価だけを保存できなかった場合は、本来の許可または停止を変えず、既存の情報流記録から補える項目を後で自動補完し、補えない項目を不明とする。本来の情報流解析や保護処理の失敗はこれと区別し、現在の安全側の停止を維持する。操作評価と試行結果そのものは外部へ送信しない。詳しい内容を残せば原因調査は容易になるが、評価のために保護内容の露出範囲を広げないことを優先する。Maniの環境では継続評価を有効にするが、一般利用者向けの初期状態では有効にしない。試行結果から改善提案Issueを作る扱いは、別の判断記録で定める。
