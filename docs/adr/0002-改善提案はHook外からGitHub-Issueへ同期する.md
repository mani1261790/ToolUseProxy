# 改善提案はHook外からGitHub Issueへ同期する

比較が成立したら、試行結果に現れた問題を未特定も含めてすべて内容非保持の改善提案Issueへつなげる。同じ判定方式、問題原因、理由番号、道具の種類が一致する問題は1つにまとめる。開いた既存Issueがあれば追記し、解決済みなら再度開いて追記し、一致するIssueがなければ新しく作成する。Issueには、対象プロジェクト数、操作数、停止確認の件数、問題原因、改善する理由、人工的な再現例の作成方針、改善後に比べる数値だけを含める。保護対象の本文、命令文、URL、接続先、ファイルの場所、個々の操作評価、プロジェクト名は含めない。

GitHubとの通信は、操作を許可または停止する処理の外で行う。投稿前に、許可された項目だけで作られていることを機械的に確認する。GitHubとの通信に失敗しても、ローカルの操作評価、試行結果、保護処理には影響させず、外部共有案を残して次回に再試行できるようにする。

改善提案Issueの作成では、コード、ブランチ、Pull Request、GitHub Projectの状態を変更しない。試行結果を忘れずに改善へつなげることを優先する一方、集計そのものの公開と自動的なコード変更は行わない。
