# ToolUseProxy

Codexがファイルを外部に送る前に、登録した秘密ファイルや、その内容をもとに作った資料が含まれていないかを調べます。たとえば、非公開の設計メモから作った報告書をGitHubに送ろうとすると、そのつながりを検出した時点で送信を止めます。無関係な受付案内なら、検査を終えた後、Codexの通常の承認手順に戻ります。

| OS | 試せる版と確認状況 |
| --- | --- |
| macOS | [テスター版](https://github.com/mani1261790/ToolUseProxy/releases/tag/tester-20261108.5)。Codex Desktopで、止めた送信を拒否するか、今回だけ許可するかを選べます。 |
| Windows | [プレビュー版](https://github.com/mani1261790/ToolUseProxy/releases/tag/windows-preview-20261108.1)。自動テストで基本動作を確認しています。「今回だけ許可」は使えません。 |
| Linux | [以前の公開版（alpha.16）の導入手順](QUICKSTART.md#以前の公開版alpha16を使う方へ)があります。Ubuntuでは自動テストと配布物の検証まで確認済みです。Macテスター版に相当するLinux版の配布と、実際の送信確認画面の検証はまだです。 |

## Macで始める

Codex Desktop、ログイン済みのCodex CLI、Python 3.11または3.12、自分のJev APIキーを用意してください。判定にはJev・Codexの利用枠を使い、操作記録や必要なファイル内容を渡すことがあります。[データの扱い](PRIVACY.md)を確認し、これらのサービスで扱えるプロジェクトを選んでください。

**1. 使いたいプロジェクトをCodex Desktopで開き、次の一文を貼り付けます。**

```text
https://github.com/mani1261790/ToolUseProxy/releases/tag/tester-20261108.5 のMac版を、今開いているプロジェクトに導入して。
```

CodexがZIPの取得・照合・展開・設定を行います。導入先を確認してください。APIキーをチャットに貼る必要はありません。

**2. 送信前の確認を有効にします。** Full Accessをオフにして、`/hooks` でこのプロジェクトのToolUseProxyの6件を信頼し、新しいチャットを開きます。 最初の依頼を送ると、Codex Desktopの右側にこのプロジェクトのログ画面が開きます。「ログを開いて」と頼む必要はありません。

**3. 守りたいファイルを登録します。** 導入しただけでは保護対象は0件です。次の例のファイル名を自分のものに置き換えて頼み、登録一覧にその名前があることを確認してください。

> .codex/tooluseproxy-review/AGENT_INSTALL.md の手順で、非公開/設計.md を保護して、登録一覧を見せて。

設定で迷ったら、[導入と初回の確認手順](QUICKSTART.md)を参照してください。

## 送信が止まったら

Macの確認画面で、どのファイルをどこへ送ろうとしているかを確認します。心当たりがなければ「拒否」、意図した送信なら「この送信を今回だけ許可する」にチェックを入れて確定します。止まった理由を詳しく知りたいときは、ログ画面で情報のつながりをたどれます。

モデルが情報のつながりを見落としたり、無関係な内容を結びつけたりすることはあります。判定が終わらなかったときも実行は止まりますが、これは漏えいを検出したという意味ではありません。

対象はCodexからToolUseProxyに届き、入力に外部送信が明示された操作です。スクリプト内部の通信やローカルサービスによる転送は検査できません。Web検索など、操作が届かないツールに秘密情報やその派生内容を入力しないでください。[対応範囲と既知の制限](SUPPORT.md)
