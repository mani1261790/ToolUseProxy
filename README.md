<h1 align="center">ToolUseProxy</h1>

<p align="center">
  <strong>AIに任せる作業にも、外へ出したくない情報がある。</strong><br>
  Codexのツール操作を調べ、保護情報の送信を実行前に止めるPlugin。
</p>

<p align="center">
  macOS / Linux · Python 3.11–3.12 · 研究用アルファ版<br>
  <a href="README.en.md">English</a>
</p>

**ToolUseProxy**は、Codexがファイルを読んだり、コマンドを実行したりする際に、保護情報が外部へ送られないかを確認するPluginです。未公開コードや研究ノート、`.env`など、利用者が選んだ情報を保護対象として登録します。

たとえば、作業中に読んだ非公開の資料が、外部サービスへのリクエストに含まれてしまう場合。ToolUseProxyは送信内容を調べ、保護情報が含まれると判定した操作を実行前に止めます。対応する操作の範囲で働く仕組みで、あらゆる情報漏えいを防げるわけではありません。

[SecHack365](https://sechack365.nict.go.jp/)で研究・開発しています。

> このbranchは **v0.2.0-alpha.2の開発版**です。公開チャンネルへの反映状況はリリース情報を確認してください。

## 主な機能

- **守る情報を選ぶ** — 利用者が指定したファイルを登録します。初期化だけで、すべてのファイルが保護対象になることはありません。
- **送信前に確認する** — ToolCallの記録を独立したCodex判定モデルに渡し、内容の依存関係と外部通信の可能性を調べます。
- **危険な操作を止める** — 対応するツール操作について、外部へ送る内容に保護内容との一致、または登録済み情報源への依存経路が見つかった場合に実行を止め、理由を示します。判定不能や時間切れは警告して継続します。
- **操作を記録する** — 呼び出したツール、保存された入力・出力、判定をローカルに記録します。利用するプロジェクトごとに設定できます。

開発版には、これらの記録をリアルタイムに読む[ログビューアー](#ログを見る)もあります。

## 対応環境

| 項目 | 要件 |
| --- | --- |
| OS | macOS / Linux。Windowsは実験段階です。 |
| Python | 3.11 または 3.12 |
| Codex | Pluginに対応したCodex CLIまたはCodex Desktop |

現在は研究用のアルファ版です。公開版と開発中の`main`には差分があるため、通常の導入には検証済みの公開版を配信する`public-alpha`を使います。詳しい環境別の状況は[対応環境と既知の制限](SUPPORT.md)にまとめています。

## 導入と初期設定

v0.2は開発中です。公開チャンネルを更新したとは扱わず、導入時に実際の版を確認してください。
設定では、ToolCallの入力・出力と必要な資源の証拠を判定用Codexへ渡すこと、バックグラウンド解析もモデルを利用すること、判定不能時に警告して継続する方針を説明します。
設定後、指定したファイルを保護対象に登録します。初期化だけで全ファイルが保護されるわけではありません。

[クイックスタート](QUICKSTART.md)に現在のコマンドをまとめています。v0.1の設定を暗黙に新方式へ移し替えません。

## ログを見る

setup時にログUIを起動します。Codexのサイドパネルで開けば、作業と判定を同じ画面で確認できます。
新しい記録は自動で表示され、プロジェクト・セッション・blockの有無で絞り込めます。
呼び出し詳細から別画面の来歴グラフを開き、資源の版やセッション間の依存を確認できます。
ログUIの接続と、実際にHookが到達して保護が働くことは別に確認します。

## 保護できる範囲

ToolUseProxyは、CodexのHookを通して受け取れるツール操作を検査します。AIモデルへの通信全体を仲介する仕組みではありません。

- Hosted Web Searchなど、Hookに現れない経路は技術的な遮断の対象外です。実行中のプロセスへの追加入力など、再検査されない操作もあります。
- 暗号化・圧縮・言い換えなど、任意の変換をすべて見抜ける保証はありません。LLMの依存推定には見逃しと誤検出があり、経路探索だけで推定の誤りを補えるわけではありません。
- 操作の記録には、コードや入力・出力、保護情報の断片が平文で残る場合があります。ログDBや実作業の画面を共有するときは、内容を確認してください。

記録はローカルに保存しますが、判定のためにToolCallのI/OをCodexへ渡します。データの扱いについては[プライバシーとデータ保持](PRIVACY.md)、操作ごとの制限は[サポート範囲](SUPPORT.md)を参照してください。

## 仕組みと研究

ToolCallをノードとし、LLMが内容の依存エッジを推定します。外部通信の際に登録情報源への到達性を機械的に調べます。送信対象の内容一致を調べるDLPも独立に併用します。内容の版と実行前後の観測を記録し、同じ資源の生成・取得が確認できる場合にセッションをまたいで来歴をつなぎます。保護情報の見逃しを減らすことと、公開してよい情報の送信を不必要に止めないことが研究課題です。

設計や評価については[新しい判定方式の設計](docs/設計/ToolCall意味依存グラフ.md)を参照してください。その他の資料は[ドキュメント索引](docs/索引.md)から探せます。
