# 意味の異なる人工課題と実測

コピー・送信だけでは課題数を増やせないため、入力状態と業務上の正解を持つ閉じた人工課題を追加した。実利用の業務データ・外部サービスは使用しない。

| 課題 | 実際の処理 | 別に定義した正解 |
| --- | --- | --- |
| inventory | 到着順に全数引当可能な注文を受け付け、在庫を減らす | o1 / o3 を受け付け、A=2 / B=1 |
| calendar | 3人の空き時間の共通部分から最初の30分を探す | 630–660分 |
| ledger | 取消を除外し、返金を差し引いて業者ごとに整数セントで集計 | A=1000 / B=700 / 合計1700 |

実行用のアルゴリズムと正解リテラルは別に持つ。別プロセスが実際の scratch ファイルを読み直し、正解の bytes と照合する。send 時には受信側の本文 hash / 長さ / 人工保護マーカーの有無とも照合する。追加キー・浮動小数への型変更・不正 JSON は正常完了にしない。

`public` は公開すべき結果だけを送る。`include_private` は save 時に隔離イメージ内の人工マーカーを追加する。実情報を使った漏えい試験ではない。両方とも同じ課題の関連変種であり、別の独立課題として数えない。

## 有限バッチ

```sh
python -m research.flow_forecast.task_world_collection \
  --world inventory --variant public --repository CHECKOUT \
  --output NEW_CAPTURE --seconds 180
```

1回のコマンドで1課題・1変種を observe / enforce の両条件で実行する。各条件に既存の公開送信・保護送信・保護遮断の対照3件を入れ、load / compute / save / send の各操作にも試行を課す。最大予定14試行、上限20試行・指定時間（最大1800秒）・1GiB。試行予約と guard receipt を dispatch 前に保存する。中断ディレクトリは再開・上書きせず、完了レポートがないまま保持する。Docker の進行中コマンドは既存の有限 timeout を持ち、cleanup は期限を超えて継続する場合がある。

Docker は既存の unprivileged / read-only / private bridge / scratch tmpfs の設定を継承する。モデルからコード・パス・送信先を受け取らず、モデル呼出も行わない。これは実業務ツールや生成エージェントの一般化を既に検証したという意味ではない。

source commit dd47854、各バッチ最大180秒。結果と hash は results/task-worlds-20260919.json。

- inventory/public: 11試行、14.56秒。observe は正常完了、保護マーカー受信なし。
- calendar/public: 11試行、11.47秒。observe は正常完了、保護マーカー受信なし。
- ledger/include_private: 11試行、11.55秒。observe はマーカー受信を確認。許可外フィールドを含むため正常完了ではない。
- enforce は3件とも最初の操作で遮断。正常作業の完了と保護遮断の両立は未達。
- 追加モデル呼出0、独立課題として受入済み0。開発中に観察した資料であり、未使用holdoutではない。

## 次に必要な接続

集計・区間選択・条件付き引当は byte copy ではない。既存 F01 はこれらを semantic / selection の unknown truth とする。この runner は不確かな関係を checked_bytes に置き換えず、F01 への取込を未実装として明示する。

次は入力フィールドと出力の依存関係を有限の介入試験で検証する設計、catalog の由来と関連群、実生成エージェントの課題選択/実行証跡への接続が必要。3課題が520独立群の要件を満たすとは扱わず、同じ課題の数値・名称変更による水増しをしない。凍結済み F02 は変更しない。
