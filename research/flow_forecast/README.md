# 小さな操作列モデル（F03 / #135）

人工データ専用の `typed-operation-markov-v1`。直近2操作を条件とするカテゴリ分布を
学習し、予測した次の操作から新しい状態を作って最大8手先まで展開する。
ニューラルモデルや事前学習済み大規模モデルではない。F02の一手・危険度・静的到達・
頻度基準との差があるかは、F04の未使用データとablationで評価する。

## 学習対象

次の操作のtokenは、道具、操作種別、結果、入力物の相対アドレス、生成物の種類、
入力から生成物への関係をひとまとまりで表す。相対アドレスは種類ごとの生成順で、
未来のファイル名を正解から予測入力へコピーしない。新しい物には予測内だけのIDを付ける。

条件はobserve/enforce、可視の課題種別、利用可能な道具、直近2操作の種別・結果・
入力物の種類と保護由来の有無・出力物の種類。root IDやbranch ID、受信証拠、
未来の停止理由は予測器へ渡さない。保護由来は可視のread/copy/encode/save/sendの
入力・出力関係から扱う限定的なもの。任意の意味や因果を推定する機能ではない。

学習にはF01のtrain partitionに属する固定分布の人工試験だけを使う。
関係tokenの教師は独立したバイト照合・受信証拠。未来の観測はteacher forcingで
1操作ずつ追加する。未観測・途中終了・根拠不明な関係はunknownで打ち切り、安全な
終了tokenを教えない。課題群ごとに正規化してから等重みで数え、同じ課題の多数の分岐が
独立課題の数を増やさないようにする。

## 展開と確率

操作tokenの条件付き確率で共同の続きの確率を計算する。個々の情報経路の辺を
独立とみなして掛け合わせる方式ではない。同じ続きの中に生じた保護sourceからsinkへの
経路を集計し、到達確率にする。sinkまで届かない部分経路も辺の採点に使える。

未知の状態・不明token・生成不能な参照はunknown probability、候補を省いた分は
other probability。保持候補の確率を再正規化して不明分を隠さない。不明・未列挙が
残る場合、単一の到達確率はNoneとし、既知候補と残った質量を報告する。
条件付き分布が未知でも、安全という予測を返さない。

設定はモデルJSONにも固定する。最大4,096条件、条件当たり128 token、beam 64、
8,192展開、状態当たり1,024経路。途中でbeamを整理して、一度に全候補の状態を
メモリへ抱えない。上限で消した確率は未列挙として残る。beamを指定して比較するときは
実際の幅を予測記録に残す。通常のpredictは固定幅64。

## 実行と再現

Python 3.11/3.12の標準ライブラリだけを使用する。requirements.txtに外部依存はなく、
学習コードは通常Pluginのpackage探索対象に含めない。コードと同梱の人工データから
生成するモデルはリポジトリと同じApache-2.0。外部の重みや学習コーパスは使用しない。

```sh
python3 -m research.flow_forecast.train \
  --dataset /absolute/path/to/sealed/dataset \
  --output-directory /new/path/model-evaluation
```

既定ではtest partitionを採点。testが空ならinsufficient_evaluation_rootsと記録し、
trainに切り替えない。明示的な `--partition train` はtraining_smoke_onlyであり、
精度や採用の証明に使わない。calibrationも明示指定できるが、このコマンド自体は
testを見て再学習・閾値選択・モデル選択を行わない。

新規出力ディレクトリに次を保存する。

- intent.json: 実行条件とF02の規約ハッシュ。
- model.json: 設定、条件付き分布、学習データ識別子、課題群、モデル全体のSHA-256。
- predictions.jsonl: 予測した操作列・物の種類と親参照・経路、確率、採点。
- report.json: 成功した処理の採点、入力・モデル・予測のdigest、CPU時間・実時間・
  プロセス全体のピークRSS、予測p95、モデルサイズ、保存前後の一致。
- failure.json: 上限超過や処理失敗。成功報告の代わりに残し、新しい出力先で再実行する。

JSONだけで保存し、pickleや実行可能コードを読み込まない。既存成果物への上書き、
schema/設定/digest不一致、重複したフィールド、不正な確率、サイズ上限超過を拒否する。
モデル版は学習データだけでなく設定と分布の内容を含むdigestに結び付く。

既定上限は全処理300秒、ピークRSS 1GiB、モデル64MiB、予測ファイル64MiB。
学習中の課題ごと・条件ごと、採点中の予測ごとに時間とRSSを検査する。
これは同期処理の協調的上限検査で、OSの強制メモリ隔離ではない。
`--seconds` と `--memory-bytes` で小さい上限を指定でき、規約の上限を広げる指定は拒否。
失敗時に自動延長・別バッチの起動はしない。

## 2026-09-18の測定

実Docker試験から封印されたF01 initial/alternateを統合した48 continuation、16 Prefix、
独立2課題群で実行。新しいHTTP試行や実機Hookは起動していない。
`/private/tmp/tooluseproxy-135-combined-dataset` を入力として、
`tooluseproxy-135-combined-smoke` / `-repeat` / `-test`（同じ/private/tmp内）へ保存した。

- 学習実時間0.0081–0.0097秒、モデル19,679 bytes。
- プロセスピークRSS約25.7–26.0 MB。モデル単体の占有メモリとは異なる。
- モデルSHA-256は両学習で
  `455ac5d2de1a10ef0b00846280b49171819f20c2200fc768d0129436475ae32c`。
- train動作確認192予測のdigestは両実行で
  `06046c6ddb0251b1fe6e1ad8b5401f28e9cc0eb7dbb0729092ba193c104f4f16`。
- 保存前と再読込後も同じ予測。testは0予測で試料不足。

これは小fixtureでの再現性と費用の測定。CPUだけを使い、加速器の性能は測っていない。
隠れた分岐が確率的なため、学習集合でも最尤の経路が全行に一致するわけではない。
F02の最終評価に必要な独立課題数を満たさず、優位性・製品導入・早期停止は未実証。
F04で比較・失敗分析を行うまで、予測を製品の停止判断へ接続しない。
